# AlioOlio

ALIO 채용공고를 아침 7시부터 저녁 7시까지 매시 정각에 확인해 Notion 캘린더로 정리하고, 조건에 맞는 신규 공고를 텔레그램으로 보내는 개인용 Python 서비스입니다. 관심 표시한 공고는 공고문 첨부까지 읽어 전형 일정과 자소서 문항, 직무 내용을 채웁니다.

## 주요 동작

- ALIO ID를 고유키로 사용하고 SQLite에 텔레그램 성공 기록을 남겨 중복 알림을 방지합니다.
- 프로그램 시작 시 즉시 보충 수집합니다. PC가 꺼져 있던 동안 등록된 공고도 마지막 성공 시각 이후 범위를 다시 조회해 알립니다.
- 첫 실행은 현재 접수 중인 공고만 Notion에 기준 데이터로 등록하고 기존 공고 알림은 보내지 않습니다.
- Notion `필터 설정` DB의 체크박스로 공식 분류와 포함/제외 키워드를 관리합니다.
- Notion `채용공고` DB에서 `캘린더 표시`를 해제하면 캘린더에서 즉시 사라집니다.
- 지원기간이 끝난 공고는 `상태`가 `마감`으로 바뀌어 캘린더에서 빠집니다. 표에는 그대로 남습니다.
- `지원 관리 등록`을 체크하면 기존 `지원 현황` DB에 회사명, 직무, 마감일, 링크를 복사합니다. 공고 링크가 이미 있으면 다시 만들지 않습니다.
- `지원 현황`의 행은 ALIO 주소에 든 공고 번호(`?seq=` 또는 `?idx=`)로 공고와 이어집니다. 기관명으로 맞추면 회차가 다른 공고나 이름이 비슷한 다른 기관에 붙어서 쓰지 않습니다.

### 관심 공고에만 하는 일

`관심`을 체크한 공고는 첨부 파일까지 내려받아 다음을 채웁니다. 사람이 적어 넣은 값은 덮지 않고 빈 칸만 채웁니다.

- **전형 일정**: 공고문에서 서류발표·필기·필기발표·면접·최종발표를 읽어 날짜 속성과 `관심 전형 일정` 캘린더에 넣습니다. 날짜를 못 뽑은 단계는 `미정`으로 남겨 직접 채울 수 있게 합니다.
- **자소서 문항**: 입사지원서·자기소개서 양식에서 문항을 뽑아 번호를 매깁니다. 양식을 안 올리는 기관은 공고문에 적힌 문항 주제라도 가져옵니다.
- **직무 내용**: 직무기술서에서 주요 업무, 필요 지식·기술, 직무 핵심역량을 읽습니다.
- **제출 리마인더**: 마감이 3일 안으로 다가왔는데 `지원 현황`이 `완료`가 아니면 매일 14시와 19시에 텔레그램으로 알립니다.

`전형 메모`에는 손댈 거리만 남습니다. 아직 비어 있는 단계, 첨부 링크, 그리고 뽑은 날짜마다 공고문 원문 문장을 함께 적습니다. 이 도구는 조용히 틀릴 수 있으므로(제출 기한을 시험일로 읽는 식) 근거를 옆에 두어 몇 초 만에 대조하게 했습니다.

## 1. Notion 준비

1. [Notion integrations](https://www.notion.so/profile/integrations)에서 내부 통합을 만들고 읽기·삽입·수정 권한을 켭니다.
2. `민수 공기업 취업 준비 (2026)` 페이지의 연결 메뉴에서 이 통합을 초대합니다. 하위 `지원 현황`에도 접근 가능한지 확인합니다.
3. `.env.example`을 `.env`로 복사하고 `NOTION_TOKEN`을 입력합니다. 페이지와 기존 지원 현황 ID는 제공된 문서 구조에 맞춰 예시값이 들어 있습니다.

프로그램은 상위 페이지 아래에 다음을 자동 생성합니다.

- `ALIO 필터 설정`: 활성화 체크박스, 분류, 값, 공식/포함/제외 규칙
- `ALIO 채용공고`: 지원기간, 캘린더 표시, 필터 일치, 공고 정보, 지원 현황 연결
- 지원 캘린더(진행 중인 관심 공고만), 관심 공고, 제외한 공고 보기

초기화를 다시 실행해 중복 DB가 생기지 않도록 생성 결과 ID는 SQLite에 보관합니다.

## 2. Telegram 준비

1. Telegram의 `@BotFather`에서 `/newbot`으로 봇을 만들고 토큰을 `.env`에 입력합니다.
2. 생성한 봇에게 메시지를 하나 보냅니다.
3. 브라우저에서 `https://api.telegram.org/bot<토큰>/getUpdates`를 열어 `chat.id` 값을 `TELEGRAM_CHAT_ID`에 입력합니다.

## 3. 실행

Python 3.11 이상에서:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -e '.[test]'
alio-olio bootstrap
alio-olio run
```

macOS에서 상시 실행하려면 `com.baeminsu.alio-olio` LaunchAgent를 씁니다. 로그인하면 뜨고,
죽으면 launchd가 다시 띄웁니다. 소스가 바뀌면 2분 안에 스스로 끝내고 새 코드로 다시 뜹니다
(상시 실행이라 고친 코드가 저절로 반영되지 않아, 실제로 옛 코드가 며칠 돌던 적이 있습니다).

```bash
launchctl print gui/$(id -u)/com.baeminsu.alio-olio   # 상태 확인
tail -f data/scheduler.log                             # 로그
```

Docker로 돌리려면 `docker compose up -d`도 됩니다. 다만 화면 글자 인식(OCR)은 macOS
Vision을 쓰므로 컨테이너 안에서는 동작하지 않고, 스캔 이미지 첨부만 건너뜁니다.

`run`은 시작 직후 한 번 동기화한 다음 아침 7시부터 저녁 7시까지 매시 정각에 ALIO를 조회합니다.
알림은 동기화할 때만 나가므로 새벽에는 울리지 않습니다. 필터 변경은 15분마다 로컬 저장 공고에
재적용하고, 제출 리마인더는 14시와 19시에 나갑니다. 네 값은 `.env`의 `SYNC_HOURS`,
`FILTER_REFRESH_MINUTES`, `REMINDER_HOURS`, `REMINDER_DAYS`로 조정합니다.

## 데이터와 장애 처리

- `data/alio_olio.db`를 백업하면 수집 이력과 중복 방지 상태를 보존할 수 있습니다.
- Telegram 전송이 실패하면 성공 기록을 남기지 않으므로 다음 동기화에서 다시 시도할 수 있습니다.
- ALIO나 Notion 호출이 실패하면 `last_successful_sync`를 갱신하지 않아 다음 실행이 누락 범위를 다시 가져옵니다.
- Notion의 `캘린더 표시`, `지원 관리 등록`은 사용자 관리 속성이며 자동 갱신이 덮어쓰지 않습니다.

## 전형 일정 추출의 한계

공고문에서 날짜를 읽는 일은 조용히 틀릴 수 있어 별도로 관리합니다.

- `tests/fixtures/corpus.json`에 실제 공고문 35건을 넣고, 원문과 대조해 확인한 85칸을
  회귀 테스트로 고정했습니다. 날짜가 아예 없는 공고, 주차로만 적은 공고, 이미지 공고문처럼
  "아무것도 안 뽑는 것이 정답"인 경우도 함께 넣어 규칙을 넓히다 엉뚱한 값이 나오면 잡히게 했습니다.
- 지금까지 잘못 읽은 날짜는 예외 없이 **라벨 옆에 있지만 그 단계의 날짜가 아닌 값**이었습니다.
  제출 기한(`8.31.(월) 11:00까지`), 준비 기간(`원활한 필기시험 진행을 위해 8.10.~8.11.`),
  일정 발표(`면접전형 일정 발표 9.14.`), 항목 번호(`2-2.`), 접수 시작일, 등록 기간의 끝
  (`필기합격자발표시 ∼ 10.14.`)입니다. 각각에 테스트가 걸려 있습니다.
- 아직 못 읽는 것: 이미지·스캔 공고문, 단계 이름과 날짜가 서로 다른 줄에 있어 열을 맞춰야
  하는 HWP 표. 이런 경우는 틀린 값을 쓰지 않고 비워 둡니다.
